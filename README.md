# llm-trace-eval

Минимальный каркас: вызов LLM с трассировкой OpenTelemetry и eval-харнесс на 50 примерах.

## Что делает

- `llm_trace_eval/client.py` — вызов модели внутри спана `llm.call` (модель, промпт, ответ, задержка, токены, ошибки).
- `llm_trace_eval/harness.py` — прогон датасета: родительский спан `eval.run`, дочерний `eval.example` на каждый пример, accuracy по точному совпадению.
- `data/eval50.jsonl` — 50 примеров (25 столиц, 25 арифметических). Это заглушка для проверки конвейера, а не бенчмарк: замени на свои данные.

## Запуск

```bash
pip install -r requirements.txt
python run.py
```

По умолчанию работает backend `mock` (без ключа, ответ всегда «42»), так что проверяется только конвейер. Реальная модель:

```bash
export ANTHROPIC_API_KEY=...
python run.py --backend anthropic --model claude-haiku-5-5
```

Результат: `results.json` (построчно), трассы: `traces.jsonl`. Для OTLP-коллектора задай `OTEL_EXPORTER_OTLP_ENDPOINT`.

## Ограничения

- Метрика только точное совпадение после нормализации; нет оценки неопределённости и детекции ошибок.
- Датасет синтетический и лёгкий.
- Один вызов на пример, без повторов и ретраев.
